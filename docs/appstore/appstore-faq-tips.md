# FAQ: Autodesk Revit App Store — что говорит сообщество

## Часто задаваемые вопросы с ответами на основе опыта разработчиков

### 📋 Структура и требования

**Q: Что такое "bundle" и почему это важно?**
A: Bundle — это стандартная структура папок, которую Autodesk использует для распространения плагинов через App Store и Design Automation. Revit скачивает bundle и развертывает его в `%ProgramData%\Autodesk\ApplicationPlugins\`. PackageContents.xml указывает Revit, где найти .addin файл и другие ресурсы.

**Q: Почему нельзя просто отправить DLL и .addin файл?**
A: Autodesk требует строгую структуру для консистентности. Все приложения должны следовать одному формату, чтобы App Store мог автоматизировать валидацию, установку и удаление.

**Q: Нужно ли включать RevitAPI.dll в bundle?**
A: **НЕТ.** Это частая ошибка, которую ловят при отправке. Revit уже имеет эти DLL, и их включение:
- Увеличивает размер пакета
- Может привести к конфликту версий
- Autodesk их выявляет и требует переделать

### 🎨 UI и Ribbon

**Q: Что произойдет, если я не добавлю Ribbon button?**
A: Отклонение без возможности переделать. Autodesk **требует** видимую кнопку на ленте. External Commands/Tools недостаточно.

**Q: Где найти Autodesk Icon Guidelines?**
A: В Revit SDK, папка `Help\RibbonToolHelp\` или ищите "Autodesk Icon Guidelines.pdf" в документации. Основные требования:
- 16x16 и 32x32 пикселей (обе версии)
- PNG с прозрачностью
- Четкие линии, минимум деталей
- Следовать Autodesk дизайн-языку

**Q: Что значит "SetContextualHelp()"?**
A: Это метод, который вы вызываете на RibbonButton для привязки справки к F1:
```csharp
button.SetContextualHelp(
    new ContextualHelp(ContextualHelpType.Url, 
    "https://your-site.com/help"));
// или для локального файла:
new ContextualHelp(ContextualHelpType.ChmFile, 
    @"C:\Path\To\Help.chm");
```
Autodesk проверяет, что справка работает и содержит хоть какую-то информацию.

### 📦 Упаковка и версионирование

**Q: Какой формат версии требуется?**
A: Semantic Versioning: `Major.Minor.Patch`, например:
- `1.0.0` для первого релиза
- `1.1.0` для новых фич
- `1.0.1` для исправлений

Убедитесь, что одна версия везде:
- AssemblyVersion: 1.0.0
- AssemblyFileVersion: 1.0.0
- AppVersion в PackageContents.xml: 1.0.0

**Q: Что такое ProductCode и UpgradeCode?**
A: Уникальные GUID-ы для Windows Installer:
- `ProductCode` — идентифицирует конкретное издание вашего приложения
- `UpgradeCode` — позволяет обновлениям узнавать старые версии

Генерируйте в PowerShell:
```powershell
[guid]::NewGuid().ToString()
```

**Q: Каждый раз нужны новые ProductCode и UpgradeCode?**
A: **НЕТ.** ProductCode меняется на каждую версию (1.0 vs 1.1). UpgradeCode **не меняется** — он связывает все версии одного приложения.

### 🚫 Частые ошибки (из сообщества)

**Q: "Failed to initialize the add-in because the class could not be loaded"**
A: Возможные причины:
1. FullClassName в .addin не соответствует реальному классу в DLL
2. DLL не находится по пути в Assembly элементе
3. Зависимость DLL не скопирована в тот же folder
4. IExternalApplication интерфейс не реализован

**Решение:** Проверьте пути, убедитесь что все DLL соседствуют, протестируйте локально в `%AppData%\Autodesk\Revit\Addins\2026\`

**Q: "Assembly name, version, or public key token mismatch"**
A: Вы пересобрали DLL, но .addin файл указывает на старую версию Assembly, или произошла несогласованность версий.

**Решение:** Пересчитайте AssemblyVersion, пересоберите, заново создайте .addin

**Q: Ribbon buttons не работают / не видны**
A: Частые причины:
1. Неправильная иконка (не PNG, не прозрачная, неправильный размер)
2. Иконка не найдена по пути
3. Кнопка добавлена в External Tools вместо основной ленты
4. Класс, реализующий IExternalApplication, не регистрирует кнопки

**Решение:** 
- Проверьте код в OnStartup() — там должен быть код создания ленты
- Используйте 32x32 PNG с альфа-каналом
- Положите иконку в Resources (не в bin)

**Q: "This add-in cannot be installed for all users"**
A: Проблема с правами доступа или путями в registry. Обычно происходит если:
- Пытаетесь установить в `%ProgramData%` без admin прав
- Есть конфликт с другим плагином

**Решение:** Используйте правильные пути, тестируйте с admin правами

### 🔍 Контроль качества (QA Process)

**Q: Что проверяют модераторы Autodesk?**
A: Полный чеклист:

```
✓ Bundle структура (folder.bundle, PackageContents.xml, Contents/Resources)
✓ .addin файл валидный XML, правильные пути
✓ DLL загружается, иициализируется без ошибок
✓ Ribbon button существует и видна
✓ Иконка присутствует, правильного размера
✓ Справка (F1) работает
✓ Нет RevitAPI.dll в bundle
✓ Версионирование консистентно
✓ Компания информация заполнена
✓ Лицензия и EULA понятны
✓ Описание на App Store совпадает с реальностью
```

**Q: Сколько времени занимает review?**
A: Обычно:
- Первая отправка: 2-3 недели (может быть медленнее)
- Обновления: 1-2 недели
- В пиковые сезоны может быть и месяц

**Q: Что если отклонили?**
A: Вы получите email с описанием проблемы. Обычно это:
1. Missing Ribbon button
2. Revit API DLLs in bundle
3. Wrong paths in .addin
4. Assembly version mismatch
5. Icon issues

Исправьте, сделайте новую сборку, загрузите обновление в App Store. Повторный review обычно быстрее.

### 🛠️ CI/CD и автоматизация

**Q: Как автоматизировать упаковку в CI/CD?**
A: Используйте MSBuild targets (как в RCA):

```yaml
# GitHub Actions пример
- name: Build Release
  run: dotnet build -c Release

- name: Create bundle ZIP
  run: Compress-Archive -Path "bin\Release\Rca.bundle" -DestinationPath "Rca.bundle.zip"

- name: Upload to App Store
  run: |
    # Используйте Autodesk API или веб-форму для загрузки
    # см. документацию App Store Developer Portal
```

**Q: Нужно ли подписывать DLL?**
A: Необязательно для App Store, но рекомендуется для компаний. Если подписываете:
- Используйте код-сертификат (не тестовый)
- Убедитесь что сертификат не истек
- Подпишите ВСЕ DLL в bundle одним сертификатом

### 💡 Best Practices из опыта сообщества

**1. Версионирование и обновления**
- Увеличивайте версию перед КАЖДОЙ отправкой на App Store
- Старайтесь вып ускавать обновления каждые 2-3 месяца (хотя бы для bug fixes)
- Документируйте changelog для пользователей

**2. Тестирование перед отправкой**
- Тестируйте локально на чистой машине с Revit (не только у себя)
- Проверьте на разных версиях Windows (10, 11)
- Попросите друга протестировать на его компьютере
- Убедитесь что bundle распаковывается и работает из стандартных путей

**3. Обратная связь пользователей**
- Добавьте "Report a Bug" или "Contact" в справке
- Ответьте на первые отзывы — это повысит рейтинг
- Исправляйте критические баги в течение недели

**4. Документация**
- Справка (F1) должна быть в формате HTML, CHM или ссылка на сайт
- Включите примеры использования (скриншоты, GIF)
- Объясните, зачем нужен ваш плагин новичку

**5. Лицензирование**
- Ясно опишите лицензию (MIT, GPL, Commercial, Free, etc.)
- Если платный — работайте с Autodesk по биллингу
- Укажите коды лицензирования, если нужны

### ❓ Что еще?

**Q: Могу ли я иметь несколько версий (2022, 2023, 2024, 2025, 2026) в одном bundle?**
A: Да, структура поддерживает это:
```
Rca.bundle/
├── PackageContents.xml
└── Contents/
    ├── 2022/
    │   ├── Rca.dll
    │   └── Rca.addin
    ├── 2023/
    ├── 2024/
    ├── 2025/
    └── 2026/
```

Но Autodesk рекомендует поддерживать максимум 3-4 версии за раз (очень старые удаляйте).

**Q: Могу ли я размещать исходный код на GitHub?**
A: Да, но если это коммерческое приложение, используйте private repo или лицензию которая не позволяет прямой рипофф (MIT, Apache, GPL — нет, BSD или EULA — да).

**Q: Нужна ли VSG (Trusted Signing) для App Store?**
A: Для самого App Store нет, но это усиливает доверие пользователей. Рассмотрите для production.
